## 1. Executive Summary

This proposal outlines the upstream submission strategy and logical patch series structure for integrating the `gc550` driver into the mainline Linux kernel under `drivers/media/usb/gc550/`.

The driver is architecturally mature, highly modular, fully documented, and backed by comprehensive physical validation (11,484 consecutive frames rendered across four resolutions without desyncs). 

To ensure acceptance by Linux Media Subsystem maintainers (e.g., Mauro Carvalho Chehab, Hans Verkuil, Laurent Pinchart), the codebase should be split into a clean, incremental patch series separating:
1. Core USB infrastructure, lifecycle, and driver registration.
2. Hardware register initialization, command protocol, and safety mechanisms.
3. V4L2 / Videobuf2 streaming pipeline and BT.1120 stream demuxing.
4. ALSA PCM capture subdriver for demuxed audio.
5. Telemetry strategy (transitioning the custom diagnostic ring to standard Linux tracepoints).

## 2. Diagnostic Infrastructure Evaluation (`kernel/gc550-diag.[ch]`)

The diagnostic subsystem implemented in Stage 2A/2B provides sub-microsecond hardware telemetry, event sequencing, and concurrency monitoring via a circular ring buffer and debugfs interface.

### 2.1 Technical Metrics
- **Memory Overhead:**
  - `CONFIG_GC550_DIAG=1`: Allocates `262,144` records $\times$ 80 bytes = **20,971,520 bytes (~20.0 MiB)** of kernel `vmalloc` space per device instance.
  - `CONFIG_GC550_DIAG=0`: **0 bytes**. All telemetry data structures are omitted from `struct gc550_dev`.
- **Runtime Overhead:**
  - `CONFIG_GC550_DIAG=1`: Invokes `ktime_get_raw_ns()`, atomic increment/read operations, and raw spinlock acquisition on every marker, frame transition, and URB callback. While low enough to sustain 1080p60 without frame drops, it introduces cache traffic.
  - `CONFIG_GC550_DIAG=0`: **Zero runtime overhead**. All calls in `gc550-diag.h` compile to empty static inline stubs.
- **Debugfs Interface & ABI:**
  - Exposes `/sys/kernel/debug/gc550/videoX/{diag_status, diag_reset, diag_events}`.
  - `diag_events` exports raw 80-byte binary structures (`struct gc550_diag_record`), introducing an internal binary ABI.
- **Maintenance Cost:**
  - 1,441 lines of code (`gc550-diag.c` + `gc550-diag.h`) that must be maintained and synchronized with any parser updates.

### 2.2 Upstream Evaluation and Strategic Decision
In evaluating the three architectural options:
1. **Option A: Propose upstream as optional driver feature behind `CONFIG_GC550_DIAG`**  
   *Assessment:* **High probability of rejection.** Upstream Linux Media maintainers consistently reject driver-specific 20 MiB ring buffers and proprietary binary debugfs ABIs. Upstream policy dictates using universal kernel tracing infrastructure.
2. **Option B: Maintain as an out-of-tree development patch in this repository**  
   *Assessment:* **Recommended for internal maintenance.** Having `CONFIG_GC550_DIAG` in the standalone git repository provides developers with powerful diagnostics when testing unfamiliar hardware revisions or debugging firmware anomalies.
3. **Option C: Convert to standard Linux Kernel Tracepoints for Mainline**  
   *Assessment:* **Strongest upstream architecture.** Replacing the custom ring buffer with standard kernel tracepoints (`include/trace/events/gc550.h` using `TRACE_EVENT()`) leverages the kernel's built-in `ftrace`, `perf`, and BPF infrastructure. Tracepoints have zero overhead when disabled, allocate trace buffers globally through ftrace, require no custom debugfs code, and are enthusiastically welcomed by upstream maintainers.

### Strategic Recommendation:
- **For Mainline Submission:** Exclude the custom 20 MiB debugfs ring buffer (`gc550-diag.[ch]`) from the initial upstream submission series, or replace it with lightweight standard tracepoints (`trace_gc550_*`).
- **For the Standalone Repository:** Retain `CONFIG_GC550_DIAG` (defaulting to 0) as an optional developer tool for hardware reverse-engineering.

## 3. Proposed Upstream Patch Series

The proposed series consists of **4 production patches** (plus an optional 5th patch for tracepoints):

```
[PATCH 1/4] media: gc550: add driver skeleton, Kbuild integration, and core lifecycle
[PATCH 2/4] media: gc550: add USB command bridge, hardware bootstrap, and safety gate
[PATCH 3/4] media: gc550: add V4L2 video capture and BT.1120 stream demuxer
[PATCH 4/4] media: gc550: add ALSA PCM capture subdriver for multiplexed audio
(Optional)
[PATCH 5/5] media: gc550: add tracepoints for stream parser and hardware events
```

### Patch 1: Core Driver Skeleton & Lifecycle
- **Subject:** `[PATCH 1/4] media: gc550: add driver skeleton, Kbuild integration, and core lifecycle`
- **Files Modified / Added:**
  - `drivers/media/usb/Kconfig` (adds `config VIDEO_GC550`)
  - `drivers/media/usb/Makefile` (adds `obj-$(CONFIG_VIDEO_GC550) += gc550/`)
  - `drivers/media/usb/gc550/Kbuild`
  - `drivers/media/usb/gc550/gc550.h` (core data structures and constants)
  - `drivers/media/usb/gc550/gc550-core.c` (USB probe/disconnect and refcounting)
  - `MAINTAINERS` (adds entry for AVerMedia GC550 driver)
- **Dependencies:** None.
- **Rationale:**
  - Registers the USB device ID table (`07ca:4710`, `07ca:0550`).
  - Implements `gc550_probe()` and `gc550_disconnect()`.
  - Establishes the `kref`-based device lifecycle (`gc550_dev_release()`) that prevents use-after-free conditions across V4L2 and ALSA subsystems.
  - Initializes locking primitives (`v4l2_lock`, `stream_mutex`, `cmd_lock`, `stream_lock`).
- **Upstream-Facing Concerns:** None. Standard clean USB driver registration.

---

### Patch 2: Hardware Control, Register Tables & USB Command Bridge
- **Subject:** `[PATCH 2/4] media: gc550: add USB command bridge, hardware bootstrap, and safety gate`
- **Files Modified / Added:**
  - `drivers/media/usb/gc550/gc550-cmd.c`
  - `drivers/media/usb/gc550/gc550-regtables.h`
- **Dependencies:** Patch 1.
- **Rationale:**
  - Implements the USB command protocol over Bulk OUT `0x01` and Bulk IN `0x81`.
  - Provides `gc550_i2c_write()` and `gc550_i2c_read()` to interact with on-board I2C peripherals.
  - Implements `gc550_detect_board_state()` to determine if hardware was already configured by previous sessions.
  - Embeds the 6,576-step initialization bytecode to configure the ADV7604, ADV7511, PCA9539A, TLV320AIC3x, and Lattice FPGA during cold boot.
  - **Hardware Safety Gate:** Actively inspects and rejects Atmel AT88SC CryptoMemory opcodes (`0x05`, `0x06`, `0x07`, `0x09`), permanently protecting users against hardware bricking.
- **Upstream-Facing Concerns & Solutions:**
  - *Concern:* Upstream maintainers may question placing 53 KiB of static const bytecode in `gc550-regtables.h`.
  - *Solution:* If requested during review, easily converted to a firmware blob (`request_firmware(&fw, "gc550_init.bin", dev)`).
  - *Concern:* Why not use standard kernel I2C subdev drivers (`adv7604.c`)?
  - *Solution:* Document that the I2C bus is encapsulated inside USB bulk packets behind the Cypress FX3 and Lattice FPGA packetizer; tunneling an I2C adapter over USB bulk commands would add unnecessary complexity without providing hardware-level benefits.

---

### Patch 3: V4L2 Capture Pipeline & BT.1120 Stream Demuxer
- **Subject:** `[PATCH 3/4] media: gc550: add V4L2 video capture and BT.1120 stream demuxer`
- **Files Modified / Added:**
  - `drivers/media/usb/gc550/gc550-video.c`
- **Dependencies:** Patch 1, Patch 2.
- **Rationale:**
  - Implements SuperSpeed Bulk IN `0x83` streaming using 8x 512 KiB URBs.
  - Provides Videobuf2 integration using `vb2_vmalloc_memops` and standard V4L2 ioctl operations (`vidioc_querycap`, `vidioc_enum_fmt_vid_cap`, `vidioc_g_fmt_vid_cap`, `vidioc_s_fmt_vid_cap`, `vidioc_enum_framesizes`, etc.).
  - Demuxes ITU-R BT.1120 SAV (`00 FF FF C0`) and EAV (`00 FF FF C1`) preambles from the raw transport stream.
  - Reconstructs frames across the Cypress FX3 16 KiB ping-pong DMA buffers using a dedicated 32 KiB pair-buffer staging area.
  - Handles HDMI resolution switching and drops runt frames cleanly using `VB2_BUF_STATE_ERROR`.
- **Upstream-Facing Concerns & Solutions:**
  - *Concern:* Order-7 memory allocation for 512 KiB URBs.
  - *Solution:* Functional and standard for USB 3.0 video capture; can be upgraded to `usb_alloc_coherent()` if requested by USB core maintainers.

---

### Patch 4: ALSA PCM Capture Subdriver
- **Subject:** `[PATCH 4/4] media: gc550: add ALSA PCM capture subdriver for multiplexed audio`
- **Files Modified / Added:**
  - `drivers/media/usb/gc550/gc550-audio.c`
- **Dependencies:** Patch 1, Patch 2, Patch 3.
- **Rationale:**
  - Implements a dedicated ALSA PCM capture device (`SNDRV_PCM_STREAM_CAPTURE`).
  - Demuxes 16-bit LE 48 kHz stereo LPCM packets (`00 FF FF 58` + BE32 length) multiplexed in the Bulk IN 0x83 transport stream immediately following video EAV markers.
  - Provides thread-safe ring buffer synchronization via `alsa_lock` and non-blocking notification via `snd_pcm_period_elapsed()`.
  - Implements an atomic waitqueue quiesce mechanism (`gc550_audio_quiesce()`) ensuring safe teardown without race conditions during audio close or USB disconnect.
- **Upstream-Facing Concerns:** None. Standard ALSA integration pattern.

### Patch 5 (Optional): Standard Kernel Tracepoints
- **Subject:** `[PATCH 5/5] media: gc550: add tracepoints for stream parser and hardware events`
- **Files Modified / Added:**
  - `drivers/media/usb/gc550/gc550-trace.h` (or `include/trace/events/gc550.h`)
- **Dependencies:** Patches 1–4.
- **Rationale:**

  - Provides zero-overhead runtime observability integrated directly with `perf` and `ftrace`.
