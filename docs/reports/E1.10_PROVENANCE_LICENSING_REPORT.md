## 1. Executive Summary

In accordance with **E1.10 Phase 3**, an exhaustive provenance, licensing, and copyright audit was conducted on `kernel/gc550-regtables.h` and its embedded `gc550_init_blob` array prior to upstream kernel patch preparation.

### Audit Verdict:
**Patch 2 (`media: gc550: add USB command bridge and hardware initialization`) is formally marked as `BLOCKED PENDING PROVENANCE AND LICENSING CLARIFICATION`.**

While the array functions reliably on physical hardware and has had dangerous Atmel CryptoMemory anti-clone challenges stripped, its technical origin is a **recorded USB packet capture of official AVerMedia Windows driver (`avmu3_x64.sys`) traffic**. 

Under Linux Foundation upstream guidelines and Linux Media Subsystem submission standards, merging a 53 KiB undocumented reverse-engineered binary initialization transcript directly into the kernel source tree (`.rodata`) presents substantial copyright, redistribution, and maintainability concerns that must be addressed before public mailing-list submission.

## 2. Technical Origin and Reverse-Engineering History

### 2.1 Chronological Signal Chain
The 53,146-byte initialization array originated through the following chain of custody:

1. **Original Driver Transmission (AVerMedia Technologies, Inc.):**
   The official proprietary Windows driver `avmu3_x64.sys` issues approximately 9,900 USB control/bulk requests across Bulk OUT `0x01` and Bulk IN `0x81` during device cold boot to configure on-board hardware.
2. **Reverse-Engineering & Packet Capture (2020–2021):**
   Chris Sawczuk (`ChrisAJS`) captured this initialization exchange using USB sniffing tools (USBPcap / Wireshark) while analyzing the device protocol for the open-source user-space driver project [**`ChrisAJS/lgx2userspace`**](https://github.com/ChrisAJS/lgx2userspace).
3. **Upstream MIT Publication (`lgx2userspace`):**
   Chris Sawczuk committed the extracted transaction stream into `ChrisAJS/lgx2userspace` under the **MIT License** (`src/liblgx/src/devices/lgx/Commands.cpp` and `commanddata_lgx.cpp`).
4. **Kernel Driver Re-packaging (2026):**
   Øystein Lie audited the stream for the `lgx2KernelLevel` kernel driver:
   - Stripped all Atmel AT88SC CryptoMemory opcodes (`0x05`, `0x06`, `0x07`, `0x09`) to prevent hardware lockout.
   - Formatted the remaining 6,576 operations into a packed binary C array (`gc550_init_blob[]`).
   - Integrated the array into `kernel/gc550-regtables.h` under a dual `GPL-2.0-only OR MIT` SPDX header.

### 2.2 Functional Contents of the Array
The 53,146 bytes represent 6,576 sequential bus transactions:
- **1,853 I2C Writes (Opcode `0x01`):** Targeting five discrete physical chips:
  - Analog Devices ADV7604 (HDMI receiver, EDID RAM, video ADC, clock synth)
  - Analog Devices ADV7511 (HDMI passthrough transmitter)
  - NXP PCA9539A (16-bit GPIO expander controlling board-level reset pins)
  - TI TLV320AIC3x (Stereo audio codec)
  - Lattice ECP3 FPGA (Stream packetizer and marker injector)
- **4,721 I2C Reads (Opcode `0x02`):** Primarily status polling loops recorded from the original Windows driver session.
- **1 EEPROM Read (Opcode `0x0E`):** Reading 512 bytes of hardware configuration at cold start.
- **1 Bridge Trigger (Opcode `0x08`):** Internal Cypress FX3 ARM9 firmware trigger.

## 3. Legal and Upstream Review Analysis

### 3.1 Interoperability vs. Creative Expression
In United States (*Sega v. Accolade*, *Sony v. Connectix*, *Google v. Oracle*) and European Union software copyright law (EU Directive 2009/24/EC Art. 6), functional interface specifications, protocol constants, and register configuration sequences required to achieve interoperability with hardware are generally deemed non-copyrightable functional facts.

However, upstream Linux kernel maintainership applies stricter criteria than baseline copyright defense:

### 3.2 Key Upstream Concerns
1. **Uncharacterized Proprietary Bytecode:**
   Upstream maintainers (e.g., Greg Kroah-Hartman, Hans Verkuil) consistently reject large static "black-box" register dumps embedded directly into kernel C source files. A 53 KiB binary array containing thousands of register writes without individual symbolic explanations violates kernel documentation standards.
2. **Third-Party EDID Data:**
   Steps 286–293 of `gc550_init_blob` write a 256-byte EDID structure declaring `"ADI HDMI TV"`. While standard EDID blocks are widely distributed, embedding proprietary vendor EDID binaries directly in `.c` files frequently draws scrutiny from kernel maintainers.
3. **Uncharacterized Peripheral Slaves:**
   The array contains writes to unknown I2C slave addresses (`0x4A`, `0x65`, `0x3F`) whose physical silicon identity and register maps remain unconfirmed.
4. **SPDX Declaration Scope:**
   `kernel/gc550-regtables.h` carries the SPDX identifier `GPL-2.0-only OR MIT` with `Copyright (C) 2026 Øystein Lie`. While the C array structure and formatting were authored by Øystein Lie and the reverse-engineering stream was licensed under MIT by Chris Sawczuk, the raw underlying sequence was generated by AVerMedia's proprietary driver. Upstream reviewers may challenge whether the author possesses the legal copyright to dual-license the underlying register sequences themselves.

### 3.3 The `request_firmware()` Fallacy
Converting `gc550_init_blob` into an external binary file (e.g., `gc550_init.bin`) loaded via `request_firmware()` resolves the kernel `.rodata` size complaint, but **does not resolve copyright or licensing questions**. Distributing `gc550_init.bin` in the `linux-firmware` repository still requires proving that the binary is redistributable under an acceptable open-source or vendor redistribution license.

## 4. Remediation Paths for Upstream Acceptance

To unblock Patch 2 for future upstream mainline inclusion, one of the following technical paths should be pursued:

### Path A: Register-Level Minimization & De-duplication (Recommended)
Analysis in `docs/GC550-REVERSE-ENGINEERING.md` established that approximately **4,800 of the 6,576 steps** are redundant polling reads recorded during Windows driver execution.
1. Eliminate all redundant polling reads (`0x02`), reducing the sequence strictly to necessary configuration writes (`0x01`).
2. Replace magic hex dumps with symbolic register writes to known chips using datasheet definitions:
   - ADV7604 register macros (`ADV7604_REG_...`)
   - ADV7511 register macros
   - PCA9539A GPIO directions
3. Symbolic register configuration tables written using public semiconductor datasheets have unimpeachable provenance and are standard throughout `drivers/media/`.

### Path B: Vendor Dialogue or Upstream Exemption
Seek formal clarification or public redistribution consent from AVerMedia Technologies, Inc., confirming that hardware register bootstrap sequences for the GC550 may be freely distributed in open-source Linux kernel drivers.
